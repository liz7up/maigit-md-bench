# 脉Git Markdown 渲染测试样本

给「脉Git」（com.lizhen.maigit）1.2.0 云测用的固定样本仓。克隆后在**代码**页逐个打开，按下表核对预期。

判据来自 2in1 实测标定：行内元素（行内代码 / 加粗 / 链接）每多一个约 0.65ms 主线程成本，
渲染预算 `MD_SPAN_BUDGET = 4000`，超预算落原文模式并显示横幅「内容过于密集，已用原文模式打开（渲染会卡顿）」。

## 重点看这几条

1. **`04` / `05` / `09` 必须走原文模式**，且能看到横幅；`02` / `03` 必须在 md 视图里正常排版。
   这条线守住了，说明预算判定没跑偏。
2. **`07` 不能崩**：这是之前会把进程打崩（`parseInline` shared heap OOM）的形状，现在按 8KB 切段后应正常渲染。
3. **`06` 不能因为体积被拒**：512KB 但零行内元素，应该进 md 视图。
4. **`08` 会显示截断提示，且代码块被切片**：编辑器 512KB 上限先截断（结尾 ``` 可能被截掉），渲染前会把超长代码块按行切成多个 8KB 的相邻块、逐块闭合重开——代码内容一字不改，表现是「同一段代码被分成几块显示」。这条曾经在云测机上直接崩（整块 512KB、1.2 万行走 Prism 高亮），切片后 2in1 实测 1.2s、无崩溃。

- `09-table-5k.md` 的表格在原文模式下是一堆 `|` 竖线文本，属预期。
- 若某文件的表现与上表不符，记录：文件名、是否出现横幅、是否卡顿（秒级描述）、是否崩溃。
